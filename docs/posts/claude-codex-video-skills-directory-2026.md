## 先区分“会规划”和“能出片”

清单中的项目并不是同一种产品。大致可按交付层级分成四组：

1. **渲染基础：**把 HTML、React、Remotion、Lottie 或其他代码变成确定性画面与视频，例如 [HyperFrames](https://github.com/heygen-com/hyperframes)。这类项目可控性高，但通常需要 Node.js、浏览器、字体、FFmpeg 或 CI 环境。
2. **生产系统：**把研究、脚本、素材、配音、剪辑和合成串成工作流，例如 [OpenMontage](https://github.com/calesthio/OpenMontage)。覆盖面越大，需要管理的模型、服务、密钥和人工审核节点也越多。
3. **专项 Skill：**把产品宣传、手绘故事、纸拼贴、口播包装等具体方法写成 Agent 可执行的操作说明。它可能只生成提示词或工程文件，并不一定直接交付 MP4。
4. **前期与分析：**负责剧本、拉片、分镜和创意改编。它们能改善生产决策，但不能替代渲染、剪辑和发布工具。

因此，“安装一个 Skill 就自动完成整条视频生产”通常是不准确的。阅读候选项目 README 时，应确认输入、实际输出、人工确认点、外部 API、本地依赖和失败后的恢复方式。

## 三条实用筛选路径

### 已有网页或产品界面，要做宣传片

先看“产品宣传与演示”，再判断是否愿意维护代码渲染环境。需要精确镜头、排版和版本控制时，可评估 Remotion 或 HyperFrames 方案；只要快速生成概念片时，应优先核对模型费用、品牌还原度和素材上传范围。

平替指南已经单独核验过 [video-shotcraft、HyperFrames Motion Director 等产品视频工具](/posts/agent-video-production-tools-2026)，可先用已有对比缩小候选范围。

### 已有素材，要做剪辑、字幕和 B-roll

从“剪辑与后期”开始，优先确认项目是否会扫描整个工作目录、上传原片、读取浏览器 Cookie 或调用第三方模型。客户素材或未发布内容应在隔离目录中处理，使用最小权限与短期 API Key；生成结果仍需人工检查字幕、事实和版权。

### 从主题开始，要做完整讲解或短视频

同时查看“讲解科普”“短视频与口播”和“剧本与学习”。先选前期方法，再选画面、声音与渲染链路，通常比寻找一个包办所有环节的仓库更稳妥。涉及数字人时，还要把肖像、声音、虚假背书和平台标识作为发布门槛，而不是成片后的补充检查。

## 安全评级应该怎么看

清单说明其安全等级来自对 README 和安装步骤的分析。核验日的机器数据标记 178 个项目为 `safe`、2 个为 `caution`。这个标签有助于初筛，但不能证明源码、依赖、安装脚本、远端服务或未来版本没有风险，也不能代替组织自己的供应链审查。

安装任何 Agent Skill 前，至少检查：

- `SKILL.md`、Shell/Python/Node 脚本和安装命令是否会执行远程代码；
- 依赖是否固定版本，是否包含来源不明的二进制文件；
- 需要哪些 API Key、Cookie、浏览器配置、文件权限和网络端点；
- 素材会留在本地，还是上传到模型、托管平台或分析服务；
- 仓库是否仍在维护，许可证是否覆盖实际要复制或分发的内容。

首次运行应使用隔离目录、非生产账号和无敏感信息的测试素材。`safe` 只能作为“继续检查”的信号，不能作为直接授权运行的结论。

## 许可证与内容权利是两件事

该导航清单本身以 [CC0 1.0](https://github.com/zhuyansen/awesome-claude-video-skills/blob/main/LICENSE) 发布，但每个子项目有自己的许可证；机器字段为空或显示 `NOASSERTION` 时，应回到仓库确认，而不是默认可商用。即使代码采用 MIT、Apache-2.0 或其他宽松许可证，仓库中的音乐、字体、截图、人物素材、模型权重和示例视频也可能另有条件。

公开成片前还应分别核验素材来源、人物同意、声音克隆授权、商标、字体、音乐、平台规则和生成模型条款。开源代码不自动授予第三方内容的使用权。

## 如何把这份目录用成稳定工作流

- **第一轮：**按交付目标选一个类别，只保留 5 个以内候选。
- **第二轮：**比较实际输出、依赖、数据路径、许可证和最近维护状态。
- **第三轮：**用同一份无敏感信息的测试素材做最小验证，记录安装时间、失败点、费用和人工修正量。
- **最后：**保留一个主工具和一个可替换方案，并固定已验证的版本；不要仅按 Star 或榜单排序直接进入生产。
